Track B 파이프라인 흐름

1. Match videos `data/drive_imports/batch01`의 경기 영상 10개
→
2. Sampled inference `run_player_model_on_video.py`로 detection CSV 생성
→
3. Hard frame mining `mine_video_hard_frames.py`로 low_conf / low_count / high_count 장면 수집
→
4. Upload bundle Roboflow relabeling용 ZIP, manifest, README 생성
→
5. Export retrain loop `retrain_track_b_export.py`로 정규화, 재학습, 태그 평가, hard sample 재추출

현재 병목은 모델 아키텍처가 아니라, 실제 경기 hard frame을 얼마나 일관되게 relabeling 루프로 다시 넣느냐에 있습니다.

현재 판단

지금은 effect 멀티클래스로 넓히는 단계가 아니라, player-only V5를 더 안정화하는 단계입니다. 즉, “더 복잡한 모델”보다 “실제 경기 hard frame relabeling의 품질”이 더 중요합니다.
  • 실제 영상에서 low-confidence 장면이 여전히 많음
  • non-playable scene contamination이 hard frame에 일부 섞여 있음
  • heavy occlusion 예시가 더 필요함
  • effect/object 멀티클래스 확장은 아직 이르다고 판단
